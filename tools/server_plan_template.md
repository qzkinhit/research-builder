# 交接三件套模板(小规模实验做完、只剩大规模实验时产出)

理念是理论站得住、用公认数据集在小规模上证明 idea、并据此预测放大后成立。小规模实验同样在服务器上跑，笔记本不跑实验。到这一步，服务器只负责把已验证的 idea 放大到审稿人挑不出问题的标准协议，不重新验证 idea。小规模与大规模由同一人在同一批机器上完成时不需要这三份文档。

三份文档放进仓库，分别是 `HANDOFF_TO_SERVER.md`、`experiments/SERVER_PLAN.md` 和 `experiments/BASELINE_DATASET_AUDIT.md`。

## 文档一，HANDOFF_TO_SERVER.md(接力说明)

写给服务器上的下一个执行者，按下面的顺序。

1. 一分钟定位。方法是什么，核心论点一句话。
2. 放大时不能破坏的不变式。核心论点是「不低于每个 baseline」时，每个新 baseline(包括服务器规模才加入的)都要纳入方法本体或候选组合，只当对照列会使论点失效。指到具体的代码接口。
3. 小规模阶段已完成的工作，放大时在此之上继续，不重做。包括方法与多设置的小规模验证(多种子)、已忠实复现的公认 baseline、已成稿的中英文两稿、已换成公认数据集的实验，并附证据日志的路径。
4. 服务器要做的事，按优先级排列。沿用同一个 runner，只改规模和评测协议。
5. 回填纪律。跑完由回填脚本把数字写入中英文两稿，有效才留，多种子、等预算、独立验证集。
6. 理论对服务器实验的预测，读结果之前先读，见下文。
7. 一句话的验收标准，以及一句写给导师或项目负责人的结论，说明放大后为什么不会出现 idea 不成立需要更换的情况。
8. 写作硬纪律的指针，见 `writing-deai.md` 与 `writing-playbook.md`。

## 文档二，SERVER_PLAN.md(任务、租卡、部署、一键复现)

- 每个设置一张表，列为公认数据集、公认下游模型、评测指标、小规模是否已复现、放大的规模。每一格都要是该领域公认的，不自造。
- 每个设置的公认 baseline(先调研清楚)，加一句说明方法如何把它们纳入候选组合。
- 小规模已复现的清单(已证明有效，不需重做)和放大阶段要跑的任务(按优先级，每项给卡型与时长估算)。
- 放大前还要做的小规模收尾。
- 不放大的部分及原因(哪些收益小、哪些数据集不适合)。
- 租卡。百 M 级的语言模型、视觉编码器、表格或时序基础模型，单卡通常够，A100 40GB 优先，预算紧时 24GB 显存的卡也能跑通。用平台的无卡模式装环境、下数据和调试，只在训练时开 GPU。数据放持久盘只下载一次，国内机器访问模型仓库用镜像。用 tmux 加任务队列，断线不影响。单篇论文的全部实验通常单卡 A100 三到四天，或两到三张卡并行一到两天。
- 部署步骤(可照抄执行)、每个任务的一键复现命令骨架(沿用小规模阶段的 runner，只放大规模或换标准指标)、小规模已验证清单(放大前的依据，审稿人与导师可核)。
- 标准交付物是仓库根的 `runall.sh`，四档与输入格式见 `SKILL.md` 的「改进现有论文」。新机器第一步是 `./runall.sh setup && ./runall.sh smoke`。

## 文档三，BASELINE_DATASET_AUDIT.md(防质疑核查)

以敌意审稿人的视角，沿 baseline 和数据集两条轴自查。

- 三方核对。核查结论、审稿人会提的问题和实际代码三者一致，逐条列出。
- 已做与未做。现有哪几个 baseline、缺哪些权威 baseline、数据集是否公认、哪些是小规模代理需要放大时替换。这份文档是内部材料，弱项全部列出。
- 每个未做或待替换的项对应到 SERVER_PLAN 里的一项任务。
- 结论。哪些质疑已解决，哪些留到放大阶段，为什么这样仍然站得住。

## 理论对服务器实验的预测

把论文的理论(下界、有限样本保证、响应模型)导出成可检验的预测，跑完逐条对照。

- 缩放关系。收益随某个可测量的量(例如下游模型对数据质量的敏感度)单调或线性变化，预测哪个设置收益大、哪个收窄。不符时先查噪声注入协议。
- 与规模无关的结论。理论里不依赖样本量的识别结论在任何规模都成立。放大后若某个固定的 baseline 处处最优，先查协议是否让各设置变得同质，再怀疑理论。
- 随验证集增大而收紧的保证。置信半径随验证集规模减小，报数时给出验证集与候选集的规模。
- 一张标度散点。横轴是理论量，纵轴是实测量，每个设置一个点，这是理论最直接的服务器验证。
- 协议教训。候选集、验证集、测试集三者互斥，时序数据还要在窗口之间留间隔防泄漏。小规模阶段修过的泄漏写进教训。

## 交付检查单

- [ ] 三件套齐全。
- [ ] 不变式写清(新 baseline 必须纳入方法本体，不只当对照列)。
- [ ] 每个设置的数据集、下游模型和 baseline 都是公认的，并已在小规模复现。
- [ ] 理论给出了可检验的预测，并写明不符时查什么。
- [ ] 不放大的部分已说明原因，防质疑核查两条轴的缺口都对应到任务。
- [ ] 一键复现命令骨架、租卡与时长预算、给导师的一句话结论齐全。
