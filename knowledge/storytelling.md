# 讲故事的套路

本文件管论文、本子和汇报怎样组织论证。句式、标点和禁用词在 `../writing-playbook.md` 与 `../writing-deai.md`，取舍规则在 `../writing-playbook.md` 第 3 节。润色也按本文件改写，只清标点不算润色。

三类素材各管一块。

| 要学什么 | 从哪学 |
|---|---|
| 怎么开篇、怎么递进、怎么收尾 | 用户自己的论文(`../materials/domain/`)和中文样稿(`../materials/writing-samples/`) |
| 方法、逻辑和必要性怎么论证 | 调研到的相关工作(`../researched_papers/` 与 `survey.md`) |
| 术语、记号和措辞 | 全部素材里出现过的词，不新造 |

用户没有放素材时，按本文件和 `paper-anatomy.md` 的骨架写，术语表先与用户确认。

## 段落组织的八条套路

1. 从具体代价切入。开篇给一个真实事故、一个调查数字或一个业务损失，说明问题同时削弱下游效果并抬高处理成本，不用抽象的「意义重大」。
2. 给框架命名并用一句话定位。说清它在什么和什么之间取得平衡，例如在清洗收益与人工成本之间分配预算。
3. 把问题拆成类别。把研究对象分成互不重叠的几类，每类说明它影响哪个性质，后文的方法与实验按这几类展开。
4. 方法讲动作，再讲条件。先讲清有哪几种动作或机制，再讲在什么条件下选哪一种，例如错误率高或模型敏感时倾向修复，反之倾向保留。
5. 让关键量可见。明确区分几个关键量，配一张能直接看出决策分布的图。
6. 必要性靠代价和实例论证。为什么必须做，用性能损失、成本和一个具体案例说明，不靠形容词。
7. 实验结论用对比呈现。一句话写清以多少成本达到了高成本方案的多少效果。
8. 现有做法的局限用「首先、其次、最后」分条写。本文方法的弱项是否进论文，按 `../writing-playbook.md` 第 3 节取舍。

## 动机段的标准顺序

具体代价 → 现有做法的局限(首先、其次、最后) → 基于实例的需求分析(给出具体数据表或场景) → 编号的技术挑战 → 本文贡献。

论文版本把「基于实例的需求分析」写成 Example 环境加编号的 Observation，见 `paper-anatomy.md` 的引言一节。本子版本把它写成研究现状分析加「其一、其二、其三」的挑战，见 `grant-proposal.md`。

## 教材式的概念展开

写综述、背景章或学位论文的绪论时按下面的顺序。

概念是什么 → 意义与价值(从数据准备、治理、分析几个视角) → 实际系统中的问题与实例 → 技术发展历程与评价维度。

## 一个贯穿全文的例子

用户的论文都用同一个例子串起引言、方法和实验。

- 引言用一个公开数据集的小切片说明问题，给出具体的行、列和错误。
- 方法章每个 Step 用同一个例子演示输入如何变成输出。
- 系统图下方画同一个例子的流动，见 `figure-archetypes.md`。
- 实验章的案例分析回到这个例子，报告方法在它上面的实际决策。

例子要小到读者能在脑中复算，又要真实到能引出全部的挑战。

## 改写时先查这几件事

1. 每段第一句是不是论点。不是的话把论点提到段首，证据放后面。
2. 段与段之间是否沿着上面的顺序递进。跳步的地方补一句过渡，重复的段落合并。
3. 每个论断是否有数字、实例或引用支撑。没有的论断删掉或改成能被证据支撑的说法。
4. 每个术语是否来自概念表。同一个对象用了两个名字时，统一成概念表里的那个。
