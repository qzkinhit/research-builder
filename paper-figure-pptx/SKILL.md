# 学术图与可编辑 PPT

目标是保留作者认可的图形结构，按当前研究内容校正标签，交付能继续编辑并且实际渲染检查过的插图。

## 文件分工

| 文件 | 内容 | 何时读 |
|---|---|---|
| `SKILL.md` | 工作顺序和必须遵守的规则 | 每次启动 |
| `references/paper-styles.md` | 用户参考图的存放、索引与选用方法 | 需要参考用户论文的画图风格时 |
| `references/layout-and-type.md` | 版式、字号换算、字号可调性、字体回退 | 调整密度与字号，或字体渲染出问题时 |
| `references/icon-library.md` | 图标素材库、自行设计图标、提取与归档 | 添加、选择或设计图标时 |
| `references/pptx-native.md` | 原生对象、SVG 嵌入、箭头路由、合并 PPT，及辅助脚本用法 | 处理分组、SVG、箭头或合并时 |
| `references/paper-integration.md` | 把图插回论文并同步图注与引用 | 用户要求回填论文时 |

## 工具与依赖

本技能在 Codex、Claude 等能读技能文件并运行本地工具的环境中使用，不依赖其他技能，也不要求固定的运行环境。

- 工具按当前环境发现。有 Codex 的 `load_workspace_dependencies` 时用它定位 Python、字体和渲染工具，否则用已有的 Python、LibreOffice 或 PowerPoint。
- `scripts/native_objects.py` 及其测试只用 Python 3 标准库。
- `scripts/extract_icon_library.py` 需要 Pillow，用 `python3 -m pip install Pillow` 装到当前任务环境。
- 下文命令以本技能目录为工作目录，项目输出和素材引用用项目内的相对路径。

## 第一步，确定什么要保持

- 先确认用户指的是哪张图。从当前稿的引用找到实际图文件、语言版本和可编辑 PPT，图号会随稿件变动，只凭「图 1」「图 2」容易找错。
- 确认任务类型。本技能处理系统图、动机图，以及已有图的插入和对象整理。实验数据图由项目的绘图程序生成，这里只负责插入、对象保真和可读性检查。
- 视觉依据与科学依据分开。布局、密度和图标样式以用户最近指定的 PNG、PPT 或示例为准。方法名、公式、数据和条件以当前论文与真实数据为准，参考图里的旧标签不代表新方法。
- 改已有图时先看完整渲染和对象结构，保留已被认可的模块、实例、表格和叙述顺序。用户只要稍作美化时，只调对应细节。
- 用户只要求检查分组或提供副本，而原文件已满足要求时，直接复制原始包，不重画也不重新导出。
- 高宽比由内容和参考图决定。用户规定比例时通过重排实现，不压扁原图。
- 简单示意图保持原生可编辑。已有的数据图沿用原绘图源。通用幻灯片工具的换主题、加装饰、图标转 PNG 等默认做法在这里不适用。
- 用简体中文沟通。不因为画学术图而自动加载其他研究类技能。

## 第二步，选参考

需要参考用户论文的画图风格时，读 `references/paper-styles.md`，按当前问题选叙事结构。用户没有参考图时，从仓库的 `knowledge/figure-archetypes.md` 选版式原型。参考图里的实验数值、方法条件和旧标签只属于原论文。

## 第三步，排版式、字体与图标

**留白与高度**
- 先删无效留白和冗长标签，再放大关键文字。
- 用户要求压低高度时，收紧行距、模块间距和画布边界。空隙通过重排收紧，不靠加图标填满，也不整体纵向拉伸。
- 模块内保留合理边距，文字不贴边，表格不挤出框。

**字号与字体**
- 字号只设少量层级，同级标题、正文和同类表格保持一致。用户已认可的字体、字重和层级保留。
- 微调时优先移动对象或改框的尺寸。
- 用户要求无衬线时，英文可用 Arial，中文可用微软雅黑，以可用字体和用户指定为准。
- 可读性按论文实际版心里的字号判断，公式下标、希腊字母、图例、坐标刻度和表格都要查。换算方法见 `references/layout-and-type.md`。
- 用户要能在 PowerPoint 里继续调字号。不把模板的「形状适应文字」统一改成固定小文本框，不用自动缩字抵消用户输入的字号。字号改不动、被压回或文字被裁时，按 `references/layout-and-type.md` 排查。

**颜色与图标**
- 沿用参考图的功能色、字体和线条风格。加图标时不换色、不降饱和度、不加重阴影，圆角和阴影只在现有风格允许时延续。
- 图标要能说明数据、模型、操作或结果，没有信息作用的图标不加。
- 优先复用参考图和用户素材，先看 `references/icon-library.md` 里的总览与索引。技能自带一组 16 个入门 SVG 图标，用户自己的图标库提取后放在同级目录。
- 现有素材表达不准时可以自行设计，匹配现有图标的配色、描边粗细、圆角、造型和细节密度，做成真正的 SVG 或原生形状组并归档。把 PNG 包进 SVG 不算矢量。
- 同级图标按可见轮廓统一视觉大小，等比缩放并对齐，不为统一外框而拉伸或裁切。
- 例子用符合当前方法的具象内容，展示输入怎样经过操作变成输出。示意例子要与实测结果区分开。

## 第四步，画箭头并组合对象

- 箭头连接的是有含义的输入、操作和输出。端点落在可见边界或正确的端口上，不必都接框的中心。
- 连接尽量直、短、方向清楚，必要时微调相邻模块使输出和输入在同一条视觉轴上。训练、验证、选择这些实际步骤不能为缩短箭头而跳过。
- 短连接用原生的 `rightArrow` 与 `downArrow`，箭身粗细、头部尺寸和对齐保持一致，等距的连接长度相同。长回路用简洁的细折线连接符。箭头大小不用来表示层级。用户另有要求时按其要求。
- 箭头是一个完整的原生对象，不用线段加三角形拼。
- 自绘图标的线、点、文字和底板合成一个命名的原生组。已有的完整 SVG 图标保持为单个 SVG 图片对象并附 PNG 回退，不拆成形状。图标旁的标签用原生文字。
- 数据表格保持为一个原生表格对象。整页不扁平化。
- 热力图这类含大量色块或路径的图，连同坐标、色条、图例和注释作为一个 SVG 图片对象插入并附 PNG 回退，它的 SVG 与数据源另外保存。
- 操作细节和辅助脚本见 `references/pptx-native.md`。

## 第五步，校正内容并同步论文

- 对照当前稿核对节点名称、动作定义、输入输出、必选候选、可选分支、参照策略和跨轮更新。方法里实际存在的条件要画出来，简图不能显得比方法的保证更强。
- 图内用读者需要的学术名称。构建版本词、脚本名和调试标签不出现，有正式定义的变量和模型名保留。
- 数据图保留原始测量、单位和插值定义。实测最高点不称全局最优，事后对比线不画成在线搜索轨迹，用于真值分析的坐标不当作部署输入。
- 用户要求插回论文时，才更新相关的图、图注、引用和邻近的过渡句，流程见 `references/paper-integration.md`。删除或合并旧图时处理全部引用，注意图的子图编号与定理分项同名的情况。
- 用户限定只改图时，不动正文和图注。可编辑 PPT 放进对应的 figure 目录，按核对过的引用路径导出并覆盖指定语言的图 PDF。
- 双语版本的布局、颜色、图标和方法含义保持对应，文字长度与换行分别处理。
- 有人并行编辑时，写入前重读当前文件，只改被授权的局部，不用旧备份覆盖别人的新内容。

## 第六步，交付前检查

1. 渲染最终 PPT 的每一页，逐页看完整画布和重要细节，并与参考图比较。
2. 查箭头的端点、路线和指向含义，查全部文字的换行、遮挡、下标和字体回退，重点看表头、图注、图例和画布底部。
3. 查对象结构与素材。原生图标仍是组，导入的 SVG 图标和热力图仍是单个 SVG 图片对象并带 PNG 回退，表格和独立文字仍可编辑，新增素材及来源已归档。
4. 合并 PPT 时保持比例。一个 PPT 只有一个页面尺寸，尺寸不同的源页等比居中并留白。按源页比较文字、对象数量、媒体和渲染。
5. 回填论文后重新编译或导出，查看实际插图页、图注、正文衔接和失效引用。工具警告要定位到具体对象。

交付最终文件和简短说明，写明改了什么、覆盖了哪些图文件、PPT 在哪、验证了什么、有没有改正文。

验证结论只写实际做过的检查。结构检查、LibreOffice 渲染和 PowerPoint 里的实际打开是三件事，报告时写清用的是哪一种。渲染环境缺字等问题没解决时，说明哪些检查已通过、哪些视觉验证还没做。用户已经授权的细节不反复请求确认。
