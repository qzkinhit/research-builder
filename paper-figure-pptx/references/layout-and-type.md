# 版式与字体

调整图的密度与字号，或字体渲染出问题时读本文件。

## 按参考图排版

- 先认出参考图里的主要区块、例子、表格、数据图、反馈回路和对齐线，分清哪些结构用户要求保持，哪些标签要按新稿修正。
- 「更学术」指信息清楚，不指多加灰色、阴影、卡片或抽象图标。
- 已被认可的图只做最小改动。用户随后纠正风格时以最新指示为准，被否定的做法不再沿用。
- 换字体后重新量文字宽度，旧的窄文本框要跟着调。
- 加图标前后，在同一输出宽度下比较整图高度、列间距和模块内留白。用户要求压低高度时，先用已有空间和横向对齐，不新增一排图标把图撑高。
- 同级图标按实际可见轮廓统一大小并等比缩放，标签保持原字号。把图片框设成相同宽高不等于图标一样大。

## 字号

- 先定一套可复用的字号层级，例如总标题、模块标题、正文、表格和注释。具体数值随画布、参考图和最终放置尺寸而定，不把某个项目的字号当成通用标准。
- 纸面字号按下式换算。

  `纸面字号 = PPT 字号 × 论文中图宽 / PPT 画布宽`

- 工具用 CSS 像素设字号时，先按 `1 px = 0.75 pt` 换算，宽度用同一物理单位。大画布上的 24 px 文字缩进窄版心后可能只有 4 到 5 pt。高清 PNG 和矢量格式都解决不了物理字号太小的问题。
- 没给字号目标时，按参考图、投稿模板和实际阅读效果定。正文与数据标签以 6 到 8 pt 作为检查起点，模板有明确要求时按模板。
- 空间不够时先缩短标签、调列宽、重新分配面积，不一味缩小字体。用户不许删内容而版心确实放不下时，做出尽量清楚的一版并说明这个限制。
- 数学标识用真正的下标、上标或公式对象。`Mfinal` 这样的普通字符串不算排好的公式。缺字的 Unicode 下标会在下标之间留出异常间隙，不要用。

## 表格和文本框

- 同类表格统一字号、表头高度、线宽和数字精度。
- 用实际字体检查最长的表头、策略名、正负号、百分号和三位小数，英文与中文分别查。
- 原生软件会自动调行高，表格外框尺寸限制不住。表头意外折成两行会把整张表推高，盖住下方的说明。
- 原生表格的单元格边距和内部文本框边距可能是两套属性。用当前 API 按单元格范围设边距，并核对导出的 `a:tcPr` 与 `a:bodyPr`。
- 放不下时加宽列或换成含义明确的短表头。单位、数字精度和术语含义不能为凑宽度而改。
- 旋转、居中、换行和自动缩放都在最终软件的渲染里检查，生成器自带的预览不够。

## 让用户能继续调字号

用户反馈字号改不动、只能放大一点或文字被裁切时，先分清是属性锁定还是文本适配，两者的处理不同。

| 现象或属性 | 含义 | 处理 |
|---|---|---|
| `a:normAutofit` | 在固定框内自动缩小文字，`fontScale` 会让界面上的字号与实际显示不一致 | 用户要自由调字号时取消这一策略 |
| `a:noAutofit` | 不锁字号，但文本框不随文字扩展。框窄、框矮又允许换行时，放大文字会换行、溢出或被截断 | 模板原有的 `a:spAutoFit` 不要统一改成它 |
| `a:spAutoFit` | 形状随文字扩展，和自动缩字是两回事 | 独立的标题与说明文字用它，并给初始字号留够宽高和内边距 |
| `a:spLocks` | `noTextEdit`、`noResize`、`noSelect` 限制对应的编辑，`noGrp` 只禁止组合，不锁字号 | 模板没有必要时不加这些锁 |
| `a:lnSpc/a:spcPts` 与组变换 | 固定行距或组缩放会压缩视觉间距 | 非必要时用正常的比例行距 |

- 标签与大模块的背景尽量分成独立的原生对象，用户放大文字时不用重画整个模块。
- 文字在 SVG 或图片内部时，它不是 PPT 原生文字，字号不能直接编辑，要向用户说明。
- 新建的文字组用恒等变换。已有的组要连同子坐标等效换算后才能规范化，直接把 `ext` 改成 `chExt` 会改变原图比例。
- 一段里的多个文字 run 可以各带 `sz`。改整段时选中文本，或一致更新全部普通 run 和段落默认字号。只改 `endParaRPr`、一个 run 或框的尺寸是不够的。下标与上标保留相对字号和 baseline。

**验证方法。** 在副本里各选一处普通标题、模块正文和带下标的公式，把字号明显调大，保存后重新打开，检查三件事：输入的字号是否保留，文本框是否随之调整，文字是否仍是原生可编辑对象。能操作 PowerPoint 时做实际编辑验证，否则做 OOXML 结构核验并在报告里写明只做了结构核验。交付稿恢复到已验收的字号。

## 字体回退

英文、中文、数学符号、SVG 和原生表格可能各走不同的字体路径，XML 里写了字体名不代表渲染器找得到这个字体。

1. 从当前依赖工具读取字体与渲染器的位置，不写死版本号或用户名目录。
2. 中文消失或变成方框时，先查渲染器的字体发现与配置，不急着重画文字。
3. 必要时在任务目录建 `FONTCONFIG_FILE`，列出实际字体目录和可写的缓存目录。系统字体配置和托管依赖目录不改。
4. TTC 含多个字面，选正常字重，避免误用超黑体。SVG 里的字体单独查。
5. PDF 中文不正常也可能是 Poppler 缺 CMap，PDF 本身并不缺字。先定位渲染环境，再决定是否换一个可用的渲染器。

用 LibreOffice 或 PowerPoint 渲染时，先确认当前环境装了什么版本并记下实际用的工具。一个渲染器失败时可换另一个复核，并说明两者的差异。
